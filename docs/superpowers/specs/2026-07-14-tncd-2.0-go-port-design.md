# tncd 2.0 — Go Port Design

**Date:** 2026-07-14
**Branch:** `v2-go-port`
**Status:** Approved design; umbrella spec for the 2.0 line plus phase 1 detail.

## Goals

Port tncd from Python to Go for the 2.0 line:

- **Packaging/portability:** single static cross-compiled binaries; retire the
  QEMU/Docker/fpm vendored-dependency release pipeline.
- **Redesign, not transliteration:** proper package boundaries, a reusable
  AX.25 engine, multiple client frontends, better CLI/config validation.
- **New protocol capability:** AX.25 v2.2 (SABME, mod-128, XID).
- **Platforms:** Linux multi-arch, Windows, macOS, BSDs.
- **Keep the e2e suite:** the pytest/Direwolf/PipeWire/PAT harness is retained
  as a black-box test rig (packet-browser pattern).

**Release gate:** v2.0.0 ships everything below (all four phases). Later
minor releases are for what comes after, not for deferred 2.0 scope.

## Non-goals

- TOML or any config-format migration. INI stays; a working 1.x `tncd.ini`
  must run unchanged on 2.0.
- Linux kernel AX.25 stack integration.
- SREJ (selective reject) — negotiated off in XID for 2.0; can be added later
  without protocol breakage.
- Porting the e2e harness itself to Go.

## Decisions (settled during brainstorming)

| Topic | Decision |
|---|---|
| Language/deps | Pure Go. Hand-rolled KISS framing and AX.25 codec. Only hardware deps: `go.bug.st/serial` (serial), `github.com/godbus/dbus` (BlueZ SPP). No cgo. |
| E2E tests | Keep pytest suite, moved to `e2e/`, black-box against the compiled binary (packet-browser pattern). |
| Coexistence | Python stays in-tree as the reference implementation until parity is proven; removed in phase 4. |
| Config | INI, drop-in compatible with 1.x. Better validation, `genconfig`, `check`. |
| Frontends | AGWPE (parity) + KISS-over-TCP passthrough + read-only JSON/WebSocket API. |
| AX.25 v2.2 | In scope (phase 3). KISS TNCs are byte-transparent at L2, so v2.2 is entirely host-side; peer capability is discovered via SABME with SABM fallback. |
| Platforms | Linux (amd64/386/armhf/arm64/riscv64), Windows (amd64/arm64, native service support), macOS (amd64/arm64), FreeBSD/OpenBSD/NetBSD. |
| Concurrency | Single engine goroutine owns all L2/bridge state; everything else messages it over channels. |

## Architecture

### Module & package layout

Go module: `github.com/ben-kuhn/tncd/v2` (the `/v2` path is required for a
2.x tag and enables `go install .../v2/cmd/tncd@latest`).

```
cmd/tncd/                  main: flags, config load, wiring, signals
ax25/                      exported: frame parse/build, addresses,
                           control fields (mod-8 + mod-128)
ax25/l2/                   exported: connected-mode engine (state machines,
                           timers, RR guard, coalescing)
kiss/                      exported: KISS framing/escaping + transports
                           (serial, TCP, Bluetooth SPP), init/exit strings
agwpe/                     exported: AGWPE header/frame encode-decode
internal/bridge/           coordinator: connections table, dispatch,
                           echo suppression
internal/frontend/agwpe/   AGWPE TCP server
internal/frontend/kisstcp/ KISS-over-TCP passthrough server (phase 2)
internal/frontend/api/     JSON/WebSocket API (phase 2)
internal/config/           INI load, validation, example generation
e2e/                       pytest suite (moved from tests/)
```

`ax25`, `kiss`, and `agwpe` are exported deliberately — they are the
reusable-library payoff of the port. Policy-shaped code (bridge, config,
frontends) stays `internal/`.

### Concurrency model

One **engine goroutine** owns all mutable L2/bridge state and runs a `select`
loop over channels:

- inbound frames from the transport reader goroutine(s)
- commands from frontend clients (connect, send, register callsign, …)
- timer expiries (T1 retransmit, RR-guard window, exit delays)

No mutexes on the hot path; nothing outside the engine touches connection
state. Frontends run their own accept/read goroutines but only send messages.
Each transport has one reader goroutine (feeding the engine) and one writer
goroutine draining a per-port TX queue — I-frame coalescing happens at
dequeue, as `_drain_outbound` does today.

This mirrors the asyncio event-loop serialization the 1.x half-duplex fixes
depend on. The Python `call_soon` poll-response deferral translates to: the
engine drains all ready inbound frames before answering a poll.

## AX.25 L2 engine

The connected-mode logic is a **behavioral port**, not a rewrite from spec.
Every hard-won 1.x behavior is an explicit requirement and a named Go test:

- SABM/UA handshake; DISC/DM handling; connection ownership by registered
  callsign ('X' frames)
- I-frame N(S)/N(R) sequencing and duplicate detection
- 3-second duplicate RR F=1 guard (`_send_rr_guarded`)
- Poll response deferred until queued inbound I-frames advance `recv_seqno`
- DM in response to I-frames for unknown connections (clears stale sessions)
- Backwards-N(R) protection in ack processing
- I-frame coalescing up to 256 bytes at TX-drain time
- Y-frame reports `unacked + queued` (Direwolf-compatible, PAT flow control)
- SABME handling: DM rejection until phase 3, then full v2.2

### AX.25 v2.2 (phase 3)

KISS TNCs never parse the AX.25 control field — in KISS mode the TNC is a
byte-transparent layer-1 framer (evidence: SABMEs from Direwolf already pass
through 1980s TNC firmware into tncd 1.x today, which is how 1.x knows to DM
them). v2.2 is therefore entirely host-side; there is no modem capability to
detect. Peer capability is discovered over the air:

1. Outgoing connect sends SABME.
2. UA → mod-128 session. DM/FRMR → retry with SABM → mod-8 session
   (Direwolf's own strategy). T1 retry exhaustion on SABME also triggers
   fallback (for peers that silently drop it).
3. Incoming SABM vs SABME selects the mode directly.

Scope: SABME accept + initiate, mod-128 sequence numbers (2-byte control
fields), XID negotiation (window, N1, version); SREJ negotiated off.
Per-port config `ax25_version = 2.0 | 2.2`, default 2.2 for outgoing with
auto-fallback. Max frame size remains per-port config (small-buffer TNCs;
same constraint as PACLEN under v2.0).

## KISS transports

Three implementations behind one interface:

- **Serial** — `go.bug.st/serial` (pure Go, cross-platform). Explicit DTR/RTS
  control preserves the HUPCL-style "don't reset the TNC on open/close" fix
  portably. Hardware flow control is easily configurable per port
  (`rtscts`, default off, matching 1.x) — some interfaces wire RTS to PTT
  (e.g. Digirig), so asserting it keys the transmitter.
- **TCP** — as today.
- **Bluetooth SPP** — BlueZ D-Bus, Linux only. On Windows/macOS, Bluetooth
  TNCs are reached through the OS virtual COM port via the serial transport.

Full TNC lifecycle parity: `init_string`/`init_delay`, KISS exit
`\xc0\xff\xc0` on graceful shutdown gated by `send_kiss_exit`,
`host_exit_string`/`exit_delay`, reconnect with backoff for Bluetooth/TCP.

## Frontends

### AGWPE (phase 1)

Straight parity: all frame kinds handled in 1.x (R, G, g, X/x, M, V, C, D, d,
K, k, y, Y, m, …), exact payload sizes pe expects, `*** CONNECTED To Station`
(incoming) vs `*** CONNECTED With Station` (outgoing) conventions, callsign
registration driving connection ownership. Wire format in `agwpe/`; server
policy in `internal/frontend/agwpe`.

### KISS-over-TCP passthrough (phase 2)

One listener (Direwolf-8001-style); the KISS command-byte port nibble maps to
`[client.N]` port numbers, so multiport works for free. All connected clients
receive every RX frame; their TX frames enter the same per-port TX queue as
the L2 engine's, sharing channel timing discipline. Lets KISS-native apps
(woad, mobile clients) coexist with AGWPE clients on one TNC. Disabled by
default; `[kisstcp]` section. Echo semantics between clients are resolved in
the phase-2 spec.

### JSON/WebSocket API (phase 2)

Read-only in 2.0: `GET /api/status` (version, ports, TNC state),
`GET /api/connections`, WebSocket `/api/events` streaming structured monitor
events (decoded heard frames, connects/disconnects, TX/RX counters) — the
AGWPE `m` stream as JSON for web tooling. Control actions deferred. Disabled
by default; `[api]` section.

## Config & CLI

- INI via `gopkg.in/ini.v1` (pure Go). Same sections/keys as 1.x
  (`[server]`, `[client.N]`, `[kiss.N]`); a working 1.x config runs
  unchanged. New optional keys/sections only add (`ax25_version`,
  `[kisstcp]`, `[api]`).
- Validation at startup: file/line-precise errors, unknown-key warnings with
  did-you-mean suggestions, cross-field checks (e.g. `type = serial` without
  `device`).
- CLI: `tncd -c /etc/tncd.ini` stays canonical (systemd units unchanged
  except binary path). Added: `tncd check -c file`, `tncd genconfig`
  (emits the fully-commented example config), `tncd version`, `--log-level`.

## Testing

- **Go unit tests** replace `tests/test_tncd.py`: golden-bytes codec tests
  for `ax25/` and `agwpe/` (byte-for-byte against frames captured from the
  Python implementation and pe), behavioral tests for `ax25/l2` with each
  1.x regression fix as a named test.
- **pytest e2e** moves to `e2e/` with its own `pytest.ini` and
  `requirements-test.txt`. Binary discovery: `TNCD_BIN` env var →
  `shutil.which("tncd")` → local build output. During coexistence `TNCD_BIN`
  can point at `python tncd.py` for test-by-test parity comparison. The known
  machine-specific PipeWire dual-instance flake in `TestMultiPort` remains
  documented, not a gate.
- **OTA gates**: real-hardware validation happens twice. Serial TNC
  round-trips (KPC+, PK-232, TS-2000) are part of the **phase 1 exit
  criteria** alongside the e2e pass — the serial/DTR/init-string paths are
  where a pure-software pass can lie, and phases 2–4 build on top of them.
  Before any **v2.0.0 tag**, the full hardware matrix is revalidated:
  the serial TNCs plus Bluetooth (Mobilinkd TNC3/TNC4 over BlueZ D-Bus SPP),
  which otherwise has no hardware gate. OTA test builds install via the
  interim `tncd-go` Nix package (see Packaging & release), keeping the
  production `tncd` service untouched.
- **CI:** `go test` + vet/lint + full cross-compile matrix on every PR.
  E2E stays local (needs PipeWire/Direwolf/PAT).

## Packaging & release

- Plain `GOOS`/`GOARCH` cross-compilation of static binaries replaces the
  QEMU/Docker/fpm pipeline: linux amd64/386/arm(GOARM=6)/arm64/riscv64,
  windows amd64/arm64, darwin amd64/arm64, freebsd/openbsd/netbsd
  amd64/arm64.
- `.deb`/`.rpm` via **nfpm** (pure-Go packager). Signed APT/RPM repos,
  Cloudflare Pages site (tncd.dev), AUR PKGBUILD, and GitHub Release flow
  all preserved with a much shorter workflow.
- Nix: `buildGoModule`; `services.tncd.*` module options preserved.
  Distribution stays via the nix-ham-packages repo
  (`~/dev/nix-ham-packages/tncd/`), as with 1.x. During development,
  nix-ham-packages carries an interim **`tncd-go`** package built from the
  `v2-go-port` branch, so OTA testing runs on the station without touching
  the production `tncd` package; at 2.0.0 release `tncd` itself moves to
  the Go build and `tncd-go` is retired.
- Windows: `tncd.exe` with native service support (`x/sys/windows/svc`).
- macOS/BSD: tarballs. Homebrew tap possible later, not gating.

## Phasing

All phases land sequentially on `v2-go-port`; each gets its own spec (where
needed) and implementation plan. This document is the umbrella plus phase 1
detail.

1. **Core port** — scaffold, packages, mod-8 L2 engine, serial/TCP/Bluetooth
   transports, AGWPE frontend, INI config. Exit: full e2e pass against the
   Go binary **plus** serial TNC OTA round-trips (KPC+, PK-232, TS-2000).
2. **New frontends** — KISS-over-TCP passthrough, JSON/WebSocket API
   (own spec for arbitration/echo details and API schema).
3. **AX.25 v2.2** — SABME/mod-128/XID with fallback; e2e against Direwolf's
   v2.2 mode.
4. **Platforms & release** — Windows/macOS/BSD specifics, nfpm release
   pipeline, packaging updates, docs/website, Python removal, full hardware
   matrix revalidation (serial + Bluetooth OTA), ship v2.0.0.

Migration: when 2.0.0 ships, cut a `v1` maintenance branch from `main` first,
then merge `v2-go-port` to `main`. 1.x takes critical fixes only while the
2.0 beta soaks.

## Deliberate divergences from 1.x

> **Update 2026-07-16:** these are no longer divergences. All four
> shared-channel guards (I-frame DM, DISC DM, SABM UA, SABME DM) were
> backported to the Python line and released as **v1.3.2** the same day.
> The Go port and Python ≥ 1.3.2 now behave identically; the notes below
> describe the behavior of the frozen in-tree reference (`tncd.py` @ 1.3.1),
> which predates the fix. The Go side additionally guards SABME via the same
> `IsLocal` path in `dispatchSABME`.

**No-connection DM responses gated on our own callsigns (2026-07-16).** In the
Python reference (`tncd.py:1771-1781` and `1986-1995`), an I-frame or DISC with
P=1 addressed to any callsign — including callsigns from completely foreign QSOs
on a shared channel — would unconditionally trigger a DM response if no
connection existed. During a live 145.030 MHz session, this caused tncd to
transmit a DM in response to an I-frame poll from MNWIN to WT9M-4, a QSO we
had nothing to do with. The Go port fixes this by consulting `Hooks.IsLocal`
(wired in the bridge to the AGWPE clients' `RegisteredCalls` sets) before
sending the stale-session DM: if the frame's destination is not one of our
registered callsigns we silently drop it. The tradeoff is that stale-session
cleanup via DM now requires the callsign to have been registered at least once
by a live client — a non-issue for normal operation where clients register
immediately on connect, but worth noting for cold-restart races.

**Incoming SABM gated on registered callsigns (2026-07-16).** `dispatchSABM` in
the Go port consults the same `Hooks.IsLocal` helper: if the frame's destination
is not one of our registered callsigns we silently drop it with no UA, no DM,
and no connection created, preventing tncd from hijacking connect attempts
addressed to other stations on a shared channel (`tncd.py:1844-1912` accepts
any SABM unconditionally).
